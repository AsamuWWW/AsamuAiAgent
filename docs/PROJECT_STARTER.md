# 项目起始文件（规范版）

## 1. 起始文件清单
建议将以下文件作为项目长期维护的基础文档：

- `README.md`：项目概览、快速开始、文档入口
- `docs/PROJECT_ANALYSIS.md`：项目分析（现状、优势、风险）
- `docs/PROJECT_PLAN.md`：阶段规划、里程碑、验收标准
- `docs/PROJECT_STARTER.md`：启动规范与初始化清单
- `CONTRIBUTING.md`：协作流程、提交与评审规范（建议后续补齐）
- `.env.example` 或配置模板：环境变量与必填项说明（建议后续补齐）

## 2. 初始化执行清单
- [ ] 明确项目范围与非目标（避免需求蔓延）
- [ ] 明确核心场景与最小可运行路径
- [ ] 固化本地环境与依赖服务清单
- [ ] 建立配置分层（公开模板/私有配置）
- [ ] 固化开发流程（issue -> branch -> PR -> review）
- [ ] 建立基础质量门槛（编译、测试、关键回归）
- [ ] 建立文档维护机制（变更即更新）

## 3. 文档维护规范
- 文档按“目标-现状-决策-结果”结构组织
- 涉及行为变化时，必须同步更新对应文档
- 避免写入本机路径、密钥、临时操作记录
- 每个阶段结束后更新里程碑状态与遗留问题

## 4. 下一步建议
1. 补齐 `CONTRIBUTING.md` 与配置模板文件。  
2. 为 Phase 1 拆分可执行任务并绑定负责人。  
3. 以“最小可运行链路”为主线推进首次里程碑验收。
